# SPEC — A Digital Edition of Burton's *Anatomy of Melancholy*

Status: **draft for approval**. Nothing is implemented. The facts about the source are in `SURVEY.md`, and the standing rules are in `CLAUDE.md`.
Decisions still open are marked **[D#]** and listed in `PLAN.md` § Decisions.

---

## 1. Goals and non-goals

**Goals.**
* A static, offline-capable reading edition of Burton's text, ingested from the Gowland 2021 EPUB.
* Every foreign-language passage is tagged and paired with an English translation, or marked as self-translated by Burton.
* Burton's citations are expanded, and his cross-references are linked.
* Interactive synopses.
* An index of cited authors.
* Optional glosses of obsolete words.
* Book-quality typography and accessibility.

**Non-goals for now.**
* A critical apparatus or collation of the 1621–51 editions.
* Old-spelling text. The source has none (SURVEY §1). **Decided (D3): Gowland's modernized text is the base.**
* Restoring the sidenotes Gowland pruned. **Decided (D4): not now.**
* Literary commentary.
* Any server-side component.

## 2. Sources, provenance and build profiles

Every piece of content carries a provenance (`resp`), and every build runs under a **profile** that decides which provenances may appear in the output.

| `resp` | Content | `private` profile | `public` profile |
|---|---|---|---|
| `burton` | Burton's text, sidenotes, synopses, headings (as edited by Gowland) | yes | yes, if [D1] allows |
| `gowland` | Bracketed translations `[…]`, brace interpolations `{…}`, "[Translation]" pages, endnote anchors and bodies, Penguin page numbers | yes, labelled "Gowland 2021" | **never**; the build fails on any leak |
| `djs1927` | Dell & Jordan-Smith translations, aligned from public-domain scans | yes | yes for a US audience; [D1] decides other jurisdictions |
| `machine` | Translations, source suggestions, citation expansions, author entries drafted by a model | yes, always labelled | yes, always labelled |
| `editor` | Corrections and reviews by the project owner | yes | yes |
| `wikidata` | Author dates and ids (CC0) | yes | yes |

Gowland material is kept in the base text, clearly marked, rather than discarded. That way:
1. the plain-text round-trip check against the EPUB can be exact (§9 V1);
2. the private build can use it;
3. the public build removes it with one filter.

Gowland's translations are **never sent to a model** as input. Machine translations must be independent of them (CLAUDE.md).

## 3. Identifiers and URLs

* **Unit** = the smallest structural division:
  * a Subsection (`1.2.3.4` = Partition.Section.Member.Subsection), or
  * a front-matter piece: `argument`, `dedication`, `ad-librum`, `abstract`, `djr`, `lectori`, `heraclite`.
  * Partition landing pages are `p1`, `p2`, `p3`, and synopses are `p1-synopsis` and so on.
* **Element ids** are `<unit>-<kind><n>`, with `n` counted in document order within the unit:
  * `p` paragraph, `lg` verse group, `n` sidenote, `f` foreign passage, `x` cross-reference, `c` citation (as `-n12-c2`), `q` quotation.
  * Examples: `1.2.3.4-n12`, `djr-f305`.
  * XML `xml:id` values cannot start with a digit, so **in XML** they carry a `u` prefix (`u1.2.3.4-n12`). HTML ids and URL fragments drop it (`#1.2.3.4-n12`), which HTML5 allows. Layer files use the unprefixed form. The conversion happens in exactly one function.
* **Stability.** Ids are minted once at first ingest and recorded in `data/ids/registry.tsv`, which maps an EPUB locator to our id. Locators look like `chapter001-01.xhtml#nat0001108` plus a character-offset fingerprint for sub-element items. Re-ingesting reuses the registry, so ids never renumber when the parser improves. A retired id stays reserved forever.
* **URLs.** The canonical form is `/1.2.3.4/`, which is the scholarly convention and the one Gowland's notes use. Others are `/djr/`, `/p1/`, `/p1/synopsis/`, `/authors/<author-id>/` and `/glossary/`. Every page is `…/index.html`, served by a local server (§7.5), so links use directory URLs. Deep links use `#1.2.3.4-n12`.

## 4. Content model

### 4.1 Base text: TEI-flavoured XML, one file per unit

`data/text/<unit>.xml`, generated by ingest and validated by `schema/edition.rng` (a RELAX NG subset of TEI plus an `ed:` namespace for Gowland material).

**Why XML and not JSON.** Burton's text is mixed content. Notes sit at exact positions mid-sentence, italics nest inside foreign spans, and foreign spans nest inside notes. XML represents this natively. JSON would need character offsets, which break on any edit, or verbose node trees. TEI vocabulary is also familiar to scholars, and lxml validates RELAX NG directly.

Element inventory:

| Element | Use |
|---|---|
| `div[@type=partition\|section\|member\|subsection\|front][@n][@xml:id]` | Hierarchy (full nesting in the assembled view; one subsection per file) |
| `head[@type=number\|title]` | `SUBSECT. 2.` / descriptive title. `@source="image:pg142.png"` when transcribed from an image |
| `p`, `lg`/`l`, `quote`, `list`/`item` | Prose, verse, block quotation, lists (`li.numlist`) |
| `hi[@rend=i\|sc\|sup\|symbol]` | Typography exactly as in the source. `sc` keeps the source's uppercase text, and CSS supplies the small caps |
| `foreign[@xml:lang][@xml:id]` | Every non-English passage: `la`, `grc`, `it`, `fr`, `es`, `de`, `nl`, `enm` (Chaucer), `he` (if ever found) |
| `note[@type=side][@xml:id][@n]` | **Burton's sidenote, inline at its anchor.** The marker position is the element's position, which precedes the glossed words as in the source |
| `ed:enref[@target]` | Gowland endnote anchor (`resp=gowland`) |
| `ed:trans[@for]` | Gowland bracketed translation, including the brackets as text. `@for` points to the `foreign` it renders when that can be determined |
| `ed:verse-trans` | Gowland's verse translation: a verse group whose first line opens `[` and last line closes `]`. (Class `TS*` only marks where *a* translation starts; Burton's own verse renderings carry it too and become `lg[@type=translation-block]`.) |
| `supplied[@resp=#gowland]` | `{…}` interpolations, braces kept as text |
| `pb[@n][@ed=penguin2021]` | Page markers, kept for verification and optional display (private) |
| `choice/sic + corr[@resp=#editor]` | **The only way a source defect is corrected.** The original survives in `sic` (e.g. Latin-M "Mανία"). Every use is listed in `data/manual/source-fixes.yaml` |
| `ref[@type=xref]` | Explicit internal cross-reference (resolved target in `@target`) |
| `figure/graphic` + `figDesc` | Frontispiece; synopsis and heading images (alt text written by us, `resp=editor`) |

Example (start of 1.1.1.1, abridged):

```xml
<div type="subsection" n="1.1.1.1" xml:id="u1.1.1.1" src="chapter001-01.xhtml#nat0001107">
  <head type="title"><hi rend="i">Man’s Excellency, Fall, Miseries, Infirmities; The causes of them</hi>.</head>
  <p xml:id="u1.1.1.1-p1" src="chapter001-01.xhtml#nat0001108">Man, the most excellent and noble creature of the World,
    <hi rend="i">the principal and mighty work of God, wonder of Nature</hi>, as <hi rend="i">Zoroastes</hi> calls him;
    <foreign xml:lang="la" xml:id="u1.1.1.1-f1"><hi rend="i">audacis naturae miraculum</hi></foreign><ed:trans for="u1.1.1.1-f1"> [the miracle of bold Nature]</ed:trans>,
    <hi rend="i">the</hi> <note type="side" xml:id="u1.1.1.1-n1" n="1" src="footnotesa.xhtml#TFootnote_29341"><foreign xml:lang="la" xml:id="u1.1.1.1-n1-f1"><hi rend="i">Magnum miraculum</hi></foreign><ed:trans for="u1.1.1.1-n1-f1"> [A great miracle]</ed:trans>.</note><hi rend="i">marvel of marvels</hi>, as <hi rend="i">Plato</hi>; …</p>
  <lg xml:id="u1.1.1.1-lg1">
    <l><foreign xml:lang="la" xml:id="u1.1.1.1-f4"><hi rend="i">Ut diis consimiles parturiat deos,</hi></foreign></l>
    <ed:verse-trans for="u1.1.1.1-f4"><l>[So that he who is like the gods may generate gods,]</l></ed:verse-trans>
  </lg>
  <p xml:id="u1.1.1.1-p2">(as an old Poet saith), to propagate the Church.<ed:enref target="ch1_en_1"/> …</p>
</div>
```

Unicode policy:
* Base text stores the **source code points unchanged** (no NFC/NFD rewriting, no quote changes).
* Normalized forms (NFC, unified Greek elision marks, case-folded small caps) exist only inside comparison, search and language-detection code.
* A defect is fixed only via `choice/sic/corr`.

### 4.2 Layers: JSON, keyed by stable ids, one file per unit

Layer files are under `data/layers/<layer>/<unit>.json`. They have sorted keys and are pretty-printed for clean diffs, and they are validated against `schema/layers/*.schema.json`. A layer never edits the base text. When an annotation must point *inside* running text (for example the span where Burton translates himself), it uses a **text-quote selector** `{"in": "<element id>", "exact": "...", "prefix": "...", "suffix": "..."}`. The validator checks that the selector matches exactly once. Character offsets are not used.

**`translations/`**, one record per `foreign` id:

```json
"1.1.1.1-f1": {
  "lang": "la",
  "text_sha1": "…",                      // hash of the normalized foreign text; a mismatch flags the record stale
  "kind": "phrase",                      // phrase | sentence | verse | title | name | formula | citation-text
  "self_translation": {
    "status": "none",                    // none | full | partial | paraphrase | undetermined
    "signals": ["no-gowland-bracket"],   // detector evidence that fed the verdict
    "burton_span": null,                 // text-quote selector when status != none
    "method": "model:claude-opus-5-5/st-v1", "confidence": "high"
  },
  "translations": [
    {"by": "djs1927", "where": "IA anatomyofmelanch1927burt p. 129", "text": "…", "align_score": 0.94},
    {"by": "machine", "model": "claude-opus-5-5", "prompt": "tr-v3", "date": "2026-11-02",
     "text": "the miracle of daring Nature", "literal": null, "confidence": "high", "flags": []},
    {"by": "editor", "text": "…", "date": "…", "note": "…"}
  ],
  "preferred": "djs1927",                // which one the reader shows by default (rule in §6.6)
  "source": {
    "status": "unidentified",            // identified | burton-cites | probable | unidentified
    "author": null, "work": null, "locus": null,
    "basis": null,                       // required unless unidentified: "text-match:<corpus ref>" | "burton-sidenote:1.1.1.1-n1" | "model:…"
    "verified": false
  },
  "review": {"state": "unreviewed", "by": null, "date": null}
}
```

`gowland` translations are not copied into this layer. In the private profile they are read live from `ed:trans` in the base text and offered as one more translation source.

**`citations/`**, one record per sidenote:

```json
"1.1.1.1-n3": {
  "raw": "Scalig. exercit. 365 sect. 3. Vales. de sac. Phil. cap. 5.",
  "citations": [
    {"id": "1.1.1.1-n3-c1", "raw": "Scalig. exercit. 365 sect. 3.",
     "author": "scaliger-julius-caesar", "work": "scaliger-jc.exotericae-exercitationes",
     "locus": [["exercitatio", "365"], ["section", "3"]],
     "display": "J. C. Scaliger, Exotericae exercitationes, exercitation 365, section 3",
     "status": "parsed", "confidence": "high", "method": "rules/abbrev-v2"}
  ]
}
```

Statuses are `parsed`, `partial` (author known, work or locus not) and `unidentified`. `display` contains only what was actually resolved. Burton's own book/chapter numbers are never renumbered to a modern scheme unless the mapping is recorded with a basis.

**`selftrans/`**: self-translation signals per `foreign` passage (rules only, M2; §6.2). The M5 verdict is recorded in `translations/` under `self_translation`.

**`xrefs/`**: target unit or element, status (`explicit-resolved`, `relative-proposed`, `relative-confirmed` or `unresolved`), method, and evidence quote.

Explicit references (M2, `burton xrefs`):
* Taken only when they name Burton's own divisions (Part./Memb./Subs./Sub./Mem.), and have either a cue ("see", "before", "as I have…", "in the following…") or at least two levels.
* Skipped and counted:
  * citations of other books: a locator after (`cap.`, `lib.`, `quaest.`, …) or a book-title abbreviation before;
  * a bare "Sect. N";
  * headings.
* Missing upper levels are inherited from the current subsection. A skipped middle level ("Part. 1 Subs. 2 Memb. 2") leaves the reference `unresolved` rather than guessed.

**`glosses/`**: the M5 Chaucer (`enm`) glosses, keyed by verse group, written by the translation runner.

**`obsolete/`** (M8, `burton obsolete`): obsolete English words, one record per occurrence, keyed by a registry id (`<unit>-gN`): a text-quote selector, the headword, the verdict (`webster`, `ordinary`, `other-obsolete`, `not-english`), the sense and its source, the confidence, and the ruling's model, prompt and date. Candidates are found by rule (`rules/obs-v1`: every sense in Webster 1913 marked obsolete or archaic, less `data/manual/gloss-stoplist.yaml`); a model rules on each occurrence in its sentence (prompt `obs-v1`). Gowland's glosses are not in this layer: the private build reads them from his endnotes (rule `gowland-gloss-v1`). V7 checks that every Webster sense is Webster's own words.

Source order (decided, D6, at my discretion):
1. **`gowland`**: Gowland's endnote glosses ("*hie*: Urge, hasten"). They are read from the endnotes at build time, never copied into the layer, and appear in the private build only.
2. **`webster1913`**: Webster's 1913 dictionary (public domain) for words Gowland doesn't gloss, kept locally and looked up by headword.
3. **`machine`**: a model-drafted sense, labelled, where neither source has the sense Burton means.
4. **`editor`**: your corrections, which override the rest.

Wiktionary may be consulted to check a sense but is not copied, to avoid CC BY-SA share-alike obligations on the layer. Candidate words come from a list of headwords that are obsolete or archaic in Webster 1913, intersected with Burton's vocabulary. Common archaisms that Gowland already leaves unglossed (*saith*, *hath*) are not glossed.

**Registries** (not per unit):
* `data/authors/<author-id>.yaml`: names, Burton's forms and abbreviations, dates, field, a 1–3 sentence identification, "why Burton cites them" (with counts computed from `citations/`), Wikidata QID, sources for each fact, status (`machine-draft`, `checked`), and `ambiguous_with` for unresolved identity.
* `data/works.yaml`: work ids, titles, and author abbreviation patterns.
* `data/abbreviations.yaml`: locators (`lib.` → book, `cap./c.` → chapter, `consil.` → *consilium* (case report), `tom.` → volume, `epist./ep.` → letter, `sat.` → satire, `dial.`, `fol.`, `tract.`, `hom.`, `serm.`, `lect.`, `prob.`, `aph.`, `dist.`, `quaest.`, `art.`, `Idem`, `ib./ibid.`) and author abbreviations (`Hor.` → Horace, `Tully` → Cicero, `Austin` → Augustine, and so on).
* `data/glossary.yaml`:
  * recurring Latin terms with preferred renderings and do-not-translate lists, e.g. `melancholia` → "melancholy", `hypochondriacus` → "hypochondriacal (of the upper abdomen)", `humores`, `spiritus animales` → "animal spirits", `atra bilis` → "black bile";
  * recurring formulae (`&c.`, `saith he`);
  * canonical English names for recurring authorities.

  Loaded into every translation prompt and checked after each response (§6.5).

**Synopses**: `data/synopses/p1.json`, a tree built by `burton synopses` from the shape in `data/manual/synopses/p1.yaml` (hidden-table paragraph ids only, read from the images; machine-made, with its `provenance` label) and the words of the hidden table, verbatim:

```json
{"id": "p1-syn", "part": "p1", "provenance": {"by": "machine", "model": "…", "date": "…", "status": "machine-draft"},
 "duplicates": [{"src_p": "nat0000108", "same_as": "nat0000034a", "reason": "…"}],
 "children": [
  {"id": "p1-synopsis-s1", "src_p": "nat0000034a", "img": "pg131_01",
   "text": [{"t": "In diseases consider "}, {"t": "Sect. 1 Memb. 1", "i": true}, {"t": "."}],
   "ref": [{"label": "Sect. 1 Memb. 1", "div": "1.1.1", "unit": "1.1.1.1"}],
   "children": [
     {"id": "p1-synopsis-s7", "src_p": "nat0000046", "relation": "or", "or": {"src_p": "nat0000045", "text": "Or"}, "…": "…"},
     {"id": "p1-synopsis-s22", "src_p": "nat0000127", "see": "♈", "see_target": "p1-synopsis-s23", "…": "…"}]},
  {"id": "p1-synopsis-s23", "src_p": "nat0000212", "key": {"src_p": "nat0000211", "text": "♈", "sign": "♈"}, "…": "…"}

```

Node ids are permanent: minted through the registry (unit `pN-synopsis`, kind `s`, located by the hidden-table paragraph). Text runs carry `i` (italic) and `sym` (`span.arial_bold` symbols). `ref` lists one entry per division number in the node's labels (`Subsect. 6, 7, 8` gives three); a label's missing upper levels are inherited from ancestors, from earlier siblings ("Memb. 3." heads a list) and, for a tree root, from the root printed before it (each sheet continues the numbering: "♊ Chirurgical physic … Memb. 3." is Sect. 4's, though Sect. 1 points to it). Ordinal labels ("2nd Memb.") count; a bare leading number ("2nd. Quantity.", "3. Physic") counts only where the structure file gives its level (`num`), read from a column heading (`head`: "Memb.", "Subsect.") or the first sibling's label in the image. A second paragraph printed as part of a node is its `label` ("Matter & quality." + "1st Subsect."). A section or member resolves to its first unit; a label that cannot be fully known keeps `unit: null`. `relation: "or"` with `or` records Burton's "Or" connector before a node, so the connector paragraph is used exactly once. `see` lists the cross-keys a node points to ("See ♈", "Sect. 2, A.", "♋ ♌ ♍"), each resolved in `see_target` to the node whose `key` carries it (a tree root, or an inner node such as P3's ♋); a key is a standalone paragraph (`src_p`, `text`) or a sign inside the root's text, and a key the image does not print is `supplied` with the reason. Each node keeps `src_p` (the hidden-table `<p>` id it consumes) for verification.

## 5. Pipeline

```
EPUB ──(1) unpack+pin──▶ (2) parse ──▶ (3) structure ──▶ (4) inline conversion ──▶ (5) Gowland separation
     ──▶ (6) language id ──▶ (7) id assignment ──▶ data/text/*.xml  ──(8) verify-text──▶ report
data/text + data/layers + registries ──(9) build --profile private|public──▶ site/  ──(10) verify-site──▶ report
```

1. **Unpack and pin.** Record the EPUB's SHA-256 in `data/source/SOURCE.lock`. A different file stops everything.
2. **Parse.** lxml reads the Burton files in spine order (SURVEY §2) and the four sidenote files.
3. **Structure.**
   * Units are derived from the **numbering text** of headings, not from tag levels. Combined headings are split.
   * Inherited levels are filled in from context.
   * The result is reconciled against the 149 nav keys. Every disagreement must be resolved in `structure-overrides.yaml`, or the step fails.
   * Image headings are replaced with their transcriptions.
4. **Inline conversion.**
   * `em` → `hi rend=i`, merging adjacent fragments only where the source is already contiguous.
   * Sidenote bodies are inlined at their `noteref`. The `fn123` marker text is dropped, but the number is recorded in `@n` and checked.
   * `pagebreak` → `pb`; `span.lucida` → `foreign xml:lang=enm` (candidate, confirmed in step 6); `span.arial_bold` → `hi rend=symbol`; `small_caps` → `hi rend=sc`.
5. **Gowland separation.**
   * `[…]` → `ed:trans`, with nested brackets and braces handled.
   * Verse groups are split at each `TS*` line. A group that is bracketed `[…]` from its first to its last line → `ed:verse-trans`; an unbracketed one is Burton's own rendering → `lg[@type=translation-block]`; `{…}` → `supplied`; endnote refs → `ed:enref`; `preface004`/`preface008` and the Dedication's "[Translation]" → flagged Gowland documents.
   * **Any bracket that does not directly follow a foreign-looking run goes to a review list** with a count, because some brackets may be Burton's own.
6. **Language identification** (§6.1) produces `foreign` elements with confidence. Low-confidence items go to a review queue and do not block ingest.
7. **Id assignment** using the registry.
8. **Text verification** (§9 V1–V5).
9. **Site build** (§8).
10. **Site verification** (§9 V6–V10).

The command surface is one CLI: `burton unpack | ingest | verify | align-djs | translate | expand-citations | verify-sources | build | serve | check`. `burton check` runs every verification and is what "done" means.

## 6. Languages, translation and self-translation

### 6.1 Language identification (not automatic detection alone)

Each step feeds a per-segment decision with a confidence:

1. **Script.** Greek (U+0370–03FF, U+1F00–1FFF), Hebrew and Arabic code points are tagged deterministically: `grc` for Greek, because Burton's Greek is ancient. The mixed-script defect ("Mανία") is caught by a rule that flags Latin letters adjacent to Greek.
2. **Candidate segments.**
   * Italic runs (fragments merged).
   * Verse lines.
   * Any run directly followed by a Gowland bracket, whatever its typography.
   * Text inside sidenotes outside recognized citation patterns.
   * Chaucer `lucida` spans.
3. **Scoring.**
   * A Latin form lexicon (candidate: Whitaker's WORDS word list; checked for licence in M2) against an English lexicon. The English list combines Burton's own English vocabulary, harvested from confidently English text, with a modern wordlist.
   * Latin function-word and ending features.
   * Context features: a following Gowland bracket, "saith *Seneca*", "as the Poet hath it", or a sidenote naming a classical author.
   * Small lexicons for Italian, French, Spanish, German and Dutch.
4. **Boundaries.** Segments are trimmed to the foreign words. "*the* fn *marvel of marvels*" stays English, while "*audacis naturae miraculum*" is Latin. Proper nouns and book titles inside a Latin run stay inside it. A *title* (e.g. *de civitate Dei*) is tagged `kind=title` and gets a gloss rather than a full translation.
5. **Adjudication.** Segments below the confidence threshold go to a model in batches, with context. The model's verdict is recorded as such (`method: model`). Anything still ambiguous goes to the review queue.
6. **Evaluation** (gate for M2):
   * A **hand-checked gold sample** of 600 segments, stratified: 300 italic runs, 100 roman runs next to brackets, 100 sidenote fragments, 50 verse lines, and 50 random English sentences as negatives. Labels are drafted, and the project owner reviews them all, or at minimum a random 25 % audit with zero disagreements [D7].
   * Report precision and recall per language, boundary exact-match rate, and a confusion matrix.
   * **Targets:** Latin precision ≥ 0.98 and recall ≥ 0.97; Greek 1.00/1.00; boundary exact-match ≥ 0.95.

**As implemented in M2** (`burton/ingest/langid.py`, in this order):
1. Greek, Hebrew and Arabic script runs. A verse group that is wholly Greek is tagged at `lg` level.
2. Verse groups followed by a translation group (Gowland's bracketed one or Burton's own) and made of Latin italics are tagged Latin at `lg` level.
3. Italic runs:
   * Fragments are joined across spaces, commas, full stops and `&`, but never across `: ; ? !`. A comma-separated list of short items is split into one run per item.
   * Each run is classified from function words, endings and the book lexicon, with the bracket rule first.
   * A bracket counts when it follows the run directly, or after the run's own closing stop or comma ("…&c. [Zanchius…"). The second case needs at least 3 words and a run that is not a string of abbreviations ("*Lat.* *10.* *Gr.* *Aust.* [At latitude 10° south]" is a locator).
   * Citations: digits and locators (`lib.`, `cap.`…; `&c.` is "etc.", never the locator `c.`), and lists whose every piece is an author with an abbreviated title ("*Grotius de verit.*") or a bare name. The stop after a run is part of its abbreviation. `de` before a capital is a name particle (*Hercules de Saxonia*), not Latin evidence.
   * A run that is not Latin as a whole is split and its pieces classified on their own: before a bracket, by shedding leading citation or name fragments; in a run judged English, at a sentence break ("…and all night. *Quae quidem*").
   * A run before a bracket that still isn't Latin is retried on its last fragments.
   * A Latin run sheds leading citation or name fragments and a trailing name that starts Burton's English sentence. Before a bracket it is never trimmed to a fragment with no word of 3+ letters ("Perseus P. Consuli. S.").
4. Roman text directly before a bracket, read backwards to the first English word.
5. Roman Latin runs anywhere: at least 3 Latin words, no English word, at least 60% Latin.
6. Model rulings (`burton adjudicate`) for runs the rules leave undetermined, and for capitalised runs that may be Latin terms. Low-confidence rulings are not applied.

The **book lexicon** (`data/lexicon/`) is learned from the edition itself:
* Latin: lowercase words from high-confidence rule decisions, mostly those followed by a Gowland bracket.
* English: Burton's roman running text.

It is rebuilt only by `burton lexicon`, from a rules-only ingest.

**Gold samples** (`data/eval/`, conventions in `LABELLING.md`), labelled blind and judged in place by `burton/verify/gold.py`:
* Tuning: 677 items (77 from M1 plus 600 stratified). Eight labels were corrected after a full-text review, because the labelling display had truncated them; each is noted in the file.
* Held-out rounds (`HOLDOUTS`), each drawn with its own seed and excluding every item already drawn: h1 (150 items, seen on 2026-10-20 when its errors were used to change the rules) and h2 (300 items: 150 italic, 50 roman-before-bracket, 50 sidenote, 25 verse, 25 English). **V5 gates on the newest round**; seen rounds and the tuning sample are reported, never gated on. Results: `verify/reports/langid-<date>.json`.

### 6.2 Self-translation detection

Burton often renders his Latin himself ("*Quantum mutatus ab illo?* How much altered from that he was"), either fully, partially, or as a looser paraphrase. Signals:
* **Gowland's practice.** He omits his bracket when Burton's rendering keeps most of the sense, and completes partial renderings in brackets. A Latin run with **no bracket** is a strong candidate. A bracket that is noticeably shorter than the Latin, next to English that overlaps it, suggests a partial rendering.
* **Adjacent English.** The next clause or sentence, sometimes the preceding one, and sometimes a following verse block of Burton's own English verse.
* **A model judgment.** It must return the **exact quotation** of Burton's English span. The validator rejects the judgment unless that quotation occurs exactly once within ±2 sentences of the foreign segment. This stops invented spans.

**As implemented in M2** (`burton selftrans`, rules only, `data/layers/selftrans/<unit>.json`): one record per `foreign` passage, keyed by passage id, with `by: rules`, `method: rules/selftrans-v1` and the passage's `text_sha1` (a mismatch makes the record stale). The signals are:
* `bracket`: `none`, `present` or `short`. Gowland's bracket is the `ed:trans`/`ed:verse-trans` whose `@for` names the passage. Only its presence and word count are read, never its text. `short` means a passage of 4+ words whose bracket has fewer than 0.8 × its words (the book's median ratio is about 1.5).
* `candidates`: spans of Burton's English, each a text-quote selector `{in, exact, prefix, suffix}` into the public text of the nearest element with an id (paragraph, sidenote, verse group, or the unit), labelled `by: rules`:
  * `following`: the next clause, or the next sentence when the passage ends one (`relation: clause | sentence`). A short attribution in between ("*…*, saith *Seneca*, …") is stepped over (`after_attribution`).
  * `preceding`: the clause before the passage, unless it is only an attribution ("elsewhere he saith").
  * `note-anchor`: for a passage in a sidenote, the clause that the note's anchor precedes in the main text ("*non meminit se aegrotum decubuisse*" → "could not remember that ever he was sick").
  * `verse-following`: Burton's own English verse group (`lg[@type=translation-block]`) after a verse, past Gowland's verse translation.
  * A prose span stops at the next foreign passage and is cut at 40 words. It needs at least 2 lowercase words (3 for `preceding`) and must not be Latin or a citation by the language rules.
  * Each span records `words`, `cognates` (passage words sharing their first five letters with a word of the span: *infinita*/infinite), and for `following`/`note-anchor` a gloss `cue` ("that is", "i.e.", "to wit", …).
* `signals`: a summary list (`no-gowland-bracket`, `short-gowland-bracket`, `english-follows`, `english-precedes`, `english-at-anchor`, `burton-verse-follows`, `gloss-cue`, `cognate-overlap`) that the M5 packets carry.
* Every selector is checked to match exactly once before it is written. Square brackets and braces left in the public text are Gowland's matter that ingest did not separate (Burton uses neither), so a candidate touching one is dropped and counted. V7 re-checks both.

Outcomes:
* `full`: no new translation is shown. The relationship is marked (§7.3).
* `partial`: a translation is generated only for the remainder, labelled "completing Burton's rendering".
* `paraphrase`: Burton's English is linked, and a translation is still available on demand.
* `none`: normal translation.

### 6.3 Translation sources and preference

The default order for which translation the reader shows is:

**Burton himself** > **editor** (reviewed) > **Dell & Jordan-Smith 1927** > **machine** > (private only) **Gowland 2021**.

The reader can change this order. Every displayed translation carries a visible and accessible label naming its source. Machine translations always show the model name and version, which come from the data rather than from the template.

**Dell & Jordan-Smith alignment** (`burton align-djs`):
* OCR text is downloaded once into `data/source/djs/` (gitignored, with recorded hashes).
* Dell & Jordan-Smith embedded translations *into* an English text, so alignment uses the surrounding English as anchors. Rapidfuzz matching on Burton's English before and after each foreign segment locates the corresponding stretch, and the English between the anchors is the candidate translation.
* Results carry `align_score`. Below a threshold the candidate is discarded, never shown.
* The M4 pilot measures coverage and accuracy before the full run.
* What Dell & Jordan-Smith did with the sidenotes (kept, translated or dropped) is not yet verified, and M4 checks it.

### 6.4 The translation runner (resumable script, not chat)

`burton translate` processes **packets**. A packet is up to about 20 passages from one unit with their context, and it is idempotent.

* **Queue.** All `foreign` ids that lack a current machine record. "Current" means the same `text_sha1`, prompt version and model. Ordered by unit.
* **Packet contents.**
  * The stable prefix (byte-identical across packets, so it can be cached): rules, style guide, output schema, `glossary.yaml`, abbreviations.
  * Unit header: number, title, the synopsis line.
  * For each passage: id, language, foreign text, its paragraph with the passage marked `⟦…⟧`, neighbouring paragraphs (trimmed), the sidenote(s) anchored in the same sentence (often Burton's attribution), the self-translation signals from §6.2, and any aligned Dell & Jordan-Smith text marked as a human translation.
  * **Never Gowland's brackets.**
* **Output.** Structured JSON per passage: translation, optional literal version, self-translation verdict with exact quote, source `{status, author, work, locus, basis}`, confidence, and flags (`corrupt-text`, `misquotation-suspected`, `wordplay`, `technical-medical`).
* **State.**
  * `state/translate/ledger.jsonl` is append-only: packet id, passage ids, input hash, prompt version, model, run id, status, and whatever usage figures the CLI reports.
  * On start the runner reconciles the ledger and runs only what is missing.
  * Layer files are written atomically (temporary file, then rename) after each packet validates. Killing the process at any point loses at most the in-flight packets.
* **Validation gates** (§6.5). A failure is retried once with the validator's message. A second failure goes to `state/review/translate.jsonl`.
* **Run mode (decided, D2: there is no API key).** The runner calls **Claude Code headless** once per packet, as a subprocess:
  * `claude -p --model <model> --output-format json --json-schema <schema file>`, with the packet on stdin and **all tools disabled**. The model must only read the packet, never the repository or the web. The `--json-schema` flag exists in the installed CLI (2.1.304); the remaining flags are confirmed and pinned in M1.
  * It runs under the project owner's subscription, so it is limited by **usage limits, not dollars**. Packets run sequentially (concurrency is configurable, default 1).
  * When the CLI reports a usage-limit or rate-limit error, the runner records the packet as `deferred` in the ledger, stops cleanly and prints how far it got. Re-running continues from there.
  * The ledger stores the CLI's reported session id and usage figures for each packet.
  * The model is recorded from the CLI's response, not assumed. The default is `claude-opus-5-5`; the pilot also runs `claude-sonnet-5-5` on the same 50 passages [D8].
  * If an API key is added later, an API mode (Message Batches API, structured outputs, prompt caching on the stable prefix) can be plugged into the same packet, ledger and validation code. It is not built now.
* **Throughput** is measured, not guessed. M4 records time and usage per packet and projects how many sessions the full pass needs.

### 6.5 Post-hoc checks on every machine result

* JSON schema valid, and ids match the request.
* The self-translation quote occurs exactly once in the base text near the segment.
* `source.status` is `identified` or `probable` only with a non-empty `basis`. `identified` additionally requires `verified: true`, which only the source verifier sets (below). Otherwise it is downgraded to `unidentified`.
* Glossary adherence: a glossary term present in the source but rendered differently produces a warning, counted in reports.
* Length ratio between 0.4 and 3.5 against the source, else a flag.
* The output is in English, and no untranslated Latin longer than 3 words remains unless it is quoted as a term.

**Source verifier** (`burton verify-sources`, M6): fuzzy-matches the quotation against public-domain classical texts kept locally. Candidates are the Perseus/PHI-derived corpora with compatible licences, used only for matching and never redistributed. A match sets `verified: true` with the corpus reference as `basis`. No match means the model's guess stays at most `probable`, shown as "probably".

### 6.6 Display rule summary

| Situation | Original + gloss | Interlinear | Read in English |
|---|---|---|---|
| Untranslated foreign passage | Dotted underline; tap or hover shows translation and label | Translation in smaller type beneath, with label | Translation replaces it, inside ⟨ ⟩, with its source label available on focus or tap; the original is one tap away |
| `self_translation: full` | Foreign and Burton's English are linked (both get a hairline underline; hovering one highlights the other) | "Burton translates →" pointer, no new line | Foreign text hidden, Burton's English kept; a small ⁂-style marker opens the original |
| `partial` | Gloss shows the completing translation, labelled as such | Completing translation beneath | Burton's English kept, plus ⟨completing translation⟩ |
| `kind=title/name` | Short gloss only | Short gloss | Original kept (titles are not replaced) |

The marking never relies on colour alone: it uses brackets, underline styles, labels and ARIA text.

## 7. Reader

### 7.1 Pages
* Home: title, frontispiece, contents.
* Front matter, DJR, each Partition landing (title and synopsis), and each unit.
* Authors index and one page per author with every citation.
* Glossary.
* "About this edition": sources, provenance labels, the rights statement for the active profile, and how machine translations are made and labelled.
* Settings.

### 7.2 Layout and typography
* **Font: EB Garamond (OFL), self-hosted WOFF2**, subset at build time with fontTools to the code points actually used. The OpenType features kept are `smcp`, `c2sc`, `onum`, `liga` and `kern`.
  * Real small caps for `hi[@rend=sc]` use `font-variant-caps: all-small-caps` on the source's uppercase text, so the text is unaltered.
  * **A coverage check** (§9 V9) proves every code point in the output has a glyph in the font stack. Fallbacks for astrological and apothecary signs (♈ ☌ ℞ ℥ ʒ ℈) are chosen in M3 from OFL fonts (e.g. Noto Sans Symbols 2), and Greek polytonic coverage of the chosen EB Garamond build is checked.
* **Measure** about 66 characters (≈ 34 em) and line-height about 1.45, with comfortable size steps.
* **Hyphenation**: CSS `hyphens: auto` driven by the `lang` attributes. Browser support for `la` and `grc` hyphenation is tested in M3. If it is missing, build-time soft hyphens (Pyphen) are added only inside those spans.
* **Sidenotes.**
  * At widths of 1100 px and up, they sit in a right-hand margin column aligned to their anchor. A layout pass pushes notes down to avoid overlap, and when the drift exceeds a limit the overflow collapses into a "more notes ▾" stack at the paragraph. Burton's density makes this necessary: up to dozens per page.
  * Below 1100 px, the marker opens a popover (native `popover`, positioned near the marker), with an inline-expansion fallback.
  * The marker precedes the glossed words, as in the source. Numbering restarts per unit. Ids stay independent of display numbers.
* **Themes**: light and dark, following `prefers-color-scheme`, with a toggle stored in `localStorage`. Contrast is AA at minimum.
* **Settings** (persisted): language mode, translation source order, expanded citations on/off, obsolete-word glosses (off by default), Penguin page numbers (private only), font size.

### 7.3 Navigation
* Breadcrumb Partition › Section › Member › Subsection.
* Previous/next unit.
* A contents tree with the current unit highlighted.
* A "where am I in the synopsis" link to the node that references the unit.
* Every synopsis node links into the text, and every unit links back to its synopsis node.

### 7.4 Accessibility
* `lang` is set on every foreign span (from `xml:lang`) and on `<html>`.
* Note markers are real links or buttons with `aria-describedby` / `aria-expanded`, reachable by Tab. Esc closes a popover and returns focus.
* Substituted translations carry visually hidden "translation:" text.
* Headings use a correct `h1`…`h4` outline whatever the source tags were.
* Landmarks, a skip link, reduced motion, and no hover-only content.
* Alt text for the frontispiece and the synopsis images. The synopsis tree itself is the text alternative.

### 7.5 Offline (decided, D5: a local server or installed app is enough)
* The site is served over http by a local static server: `burton serve`, a thin wrapper around Python's `http.server` on `127.0.0.1`. Opening from `file://` is not supported.
* It is an **installable PWA**: a web app manifest plus a service worker that precaches the whole site on first visit, so it then works offline without the server.
* Pages are still pre-rendered HTML with Burton's text and notes inline, so reading never depends on JavaScript. Mode switches are CSS-class toggles over that markup.
* Larger per-page layer data (translations, citation expansions, glosses) may be fetched as JSON, and scripts may be ES modules.
* Cross-site search (polish milestone) loads its index on demand.

## 9. Verification plan

A unit is **done** only when `burton check` passes for it. Every check prints **counts** and exits non-zero on failure.

**Independence rule.** EPUB-side counts are computed by a separate, deliberately simple counter (`burton/verify/epub_counts.py`) that walks the EPUB DOM between unit boundaries. It shares no code with ingest, because a verifier that reuses the parser cannot catch the parser's bugs.

| # | Check | Pass condition |
|---|---|---|
| V1 | **Text round-trip.** normalize(EPUB text of the Burton files) vs normalize(plain-text render of `data/text` **including** `ed:*` material) | Zero unexplained differences. Normalization: NFC, whitespace collapse, drop note-marker text (`fn123`, `123`), casefold `sc`, ignore the alt-text Penguin logo. Every remaining difference must match an entry in `verify/allowed-diffs.yaml` (with reason) or in `source-fixes.yaml`. The report prints differences by category with counts |
| V2 | **Per-unit counts**, EPUB vs XML vs generated HTML: sidenote anchors, sidenote bodies, Gowland endnote anchors (private), paragraphs, verse lines, `pb`, italic runs, Greek characters | All equal, or explained in `allowed-diffs` |
| V3 | **Note integrity** | Every sidenote has exactly one anchor and one body. No duplicate ids. Every `@n` sequence is gapless per unit. Known source defects (e.g. the `chi3_en30` mislink) are listed in `known-source-defects.yaml` with their resolution |
| V4 | **Script tagging** in XML and HTML | Every Greek, Hebrew or Arabic code point has an ancestor with a matching `lang`. Zero exceptions |
| V5 | **Language-ID evaluation** on the gold sample | Thresholds in §6.1. Results stored in `verify/reports/langid-<date>.json` |
| V6 | **Links** | Every `href`, `@target`, `xref`, synopsis `ref` and author link resolves. `unresolved` xrefs are rendered unlinked and counted, never guessed |
| V7 | **Layers** | Every layer key exists in the base text. Every `foreign` has a translation, a self-translation verdict, or `kind=title/name` with a gloss. Every machine record has model, prompt version and date. Every text-quote selector matches exactly once. Every `source` with status other than `unidentified` has a basis |
| V8 | **Profile leak check** (public) | Zero `gowland` elements, endnotes, page numbers or Gowland translations in `site/` (grep plus a DOM scan) |
| V9 | **Font coverage** | Every code point in `site/` is covered by the font stack. The report lists any fallback glyphs used |
| V10 | **HTML and accessibility** | Valid HTML (html5lib parse with no errors). The axe-core run has zero serious or critical violations on a sample of 20 pages (M3), then all pages (M8). Keyboard walk-through script passes |
| V11 | **Synopsis completeness** | The multiset of non-glyph hidden-table `<p>` texts equals the multiset of tree node texts, with known duplicates (`nat0000034a`/`nat0000108`) explained. Every `Subsect./Memb./Sect.` label in a node resolves to a unit |

`burton check` writes `verify/reports/latest.json` and a summary table. The build refuses to produce `site/` when any V1–V4, V6–V8 or V11 check fails ("fail loudly").

## 10. Risks

* **Copyright** of the base text and of Gowland's apparatus decides what can be published (§2, [D1]). This is not legal advice. For anything public, get it checked.
* **Sidenote completeness.** Gowland's pruning cannot be undone from this EPUB. Restoring the notes would need another source, and that is deferred (D4).
* **Usage limits.** Without an API key, the translation pass is paced by subscription limits. The runner must stop and resume cleanly, and M4 measures how long the full pass will take.
* **Language-ID boundaries** in mixed Latin–English sentences are the hardest part. The gold sample protects quality.
* **Sidenote layout density** in the margin is a real design problem, so it is prototyped in M3 on the densest unit.
* **Dell & Jordan-Smith OCR quality** may make alignment noisy. Below-threshold candidates are never shown.
* **Attribution honesty** depends on the verifier. Unverified guesses are visibly labelled or omitted.
